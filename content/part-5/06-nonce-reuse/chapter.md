# 随机数的正确用法：链上最贵的一次失误

第 3 篇讲 ECDSA 时提到随机数 `k`（`(r,s) = (k·G, k⁻¹(z + r·d))`）。你可能以为 k 只是"一个小帮手"。**这一节要告诉你：k 用错，你的私钥当场归零。** 历史上多起丢币、尤以比特币/以太坊套利机器人被盗，就是 k 复用。

## 攻击的本质：k 泄露 = 私钥泄露

若同一把私钥签名了**两条不同消息**，且两次都用了同一个 `k`：

- 因为 `r = (k·G).x`，**k 一样 → r 一定一样**（这是肉眼可辨的破绽）；
- 两条签名给出 `s1 = k⁻¹(z1 + r·d)`、`s2 = k⁻¹(z2 + r·d)`；
- **两式相减**消掉私钥项，先解出 `k`，再代回任一式解出 `d`：

```
k = (z1 - z2) / (s1 - s2)        (mod n)
d = (s1·k - z1) / r              (mod n)
```

> 运行右侧代码：我们用两笔 `r` 相同的签名，"窃取者"精确地反推出了受害者真实的私钥 `d`（二者逐字节一致）。这不是纸面推演，是几十行就能跑出来的真实攻击。

## 为什么还那么容易被触发

- 有人图省事把 k 设为**常数** → 必然复用；
- 坏的随机源（熵不够、种子复用，见第 4 篇 01/02）产生相同的 k；
- 某些实现在不同平台上 `k` 可预测，被学者用算法还原。

## 正确做法（现代钱包的标准答案）

1. **RFC6979**：从 `(私钥, 消息哈希)` **确定性派生** k——同一消息永远同一 k，但每条消息天然不同，杜绝"随机"环节，也就不存在复用了；
2. **Ed25519**（第 3 篇 06）直接**把 k 由 私钥+消息 哈希派生**，从设计上消灭"随机 k"这个变量；
3. 任何时候都别手写"随机 k"——交给经过审计的库。

> 本节和 41 / 42 是同一主题的两面：**私钥本身要真随机（熵），签名时的临时随机数 k 更要严谨**。随机数用错，是链上最贵的一次失误，也是最容易防住的一种。
