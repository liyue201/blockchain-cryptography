# Merkle 证明：轻节点如何只凭一条路径验证

上一节我们把交易攒成了一棵 Merkle 树，得到了一个"根"。但等等——**轻钱包**（比如手机钱包）没有那么大的存储，它不可能下载整个区块链。那它怎么证明"我那一笔交易确实在某个区块里"？

答案就是 **Merkle 证明（Merkle Proof）**：不用下载整棵树，只要带上从你的叶子**到根的那条路径**上的几个"兄弟哈希"即可。

## 想象一个二叉树"开关"

以 4 笔交易为例，根由 `H(topL, topR)` 构成。要证明 `Tx_B` 在树里，轻钱包只需要携带两个哈希：
- `L0`（Tx_B 的左兄弟），以及
- `topR`（Tx_B 所在半边的右半子树根）。

然后这样"往上走"：
```
从 Tx_B 出发
  拼上左兄弟 L0      → 得到 topL
  拼上右兄弟 topR    → 得到 root
比较：得到的是不是全网公布的根？
```

只要能拼回那个根，就 100% 证明 `Tx_B` 在这棵树里——**哪怕你不知道 C、D 具体是什么**。

## 为什么这件事很牛？

- 数据量从 O(n) 降到 **O(log n)**：1 万笔交易的块，证明只需要十几个哈希。
- 只要给一条路径，任何人都能独立验证；根是全网共识，无法伪造。
- 这就是轻钱包能在电脑里"只同步头部"，却安全确认自己收款的原因。

> 运行右侧代码：目标叶子 `Tx_B` 只带上 `L0` 和 `topR` 两个"兄弟"，就从下往上一步步拼回到 `root`，并于全网公布的一致。
> 你可以试着把证明路径里的某个值换掉（比如换个假兄弟），看它还能对上根吗？——对不上，证明就立即失效。
