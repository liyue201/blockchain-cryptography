# 从内容到地址：一条哈希的"派生链"

在链上，你要转钱给某人，需要一个**地址**。地址不是随机起的名，它是从你的**公钥出发、一路做哈希"派生"**出来的——这就是一条严丝合缝的派生链：

```
私钥 ──► 公钥(X,Y) ──► 公钥哈希 ──► 地址
          椭圆曲线          哈希        编码
```

## 一步步来看（对应右侧代码）

1. **私钥**：一个 256 位的随机数。谁有它，谁就拥有这笔钱。
2. **公钥**：由私钥算出来的椭圆曲线上的点。它无法反推出私钥（单向）。
3. **公钥哈希 `hash160`**：对公钥取哈希，得到 160 位（20 字节）的指纹。
   - 真实链用的公式是 `RIPEMD160(SHA256(pubkey))`；本示例用 `SHA-256` 两次近似教学。
4. **校验和**：双重 SHA-256 的前 4 字节拼在末尾，用来**检测地址是否抄错**。
5. **Base58Check 编码**：把上面一段二进制，翻译成人眼友好、且去掉了 `0 O I l` 等易混淆字符的"地址字符串"。

## 为什么要"多绕一道哈希"？

- **屏蔽公钥**：别人只知道你的"哈希后的地址"，无法从地址反推公钥→私钥。
- **容错**：哪怕打错一个字符，校验和通常就对不上，系统能立刻提示"地址无效"。
- **隐私/安全**：多一层单向哈希，等于又立了一堵墙。
