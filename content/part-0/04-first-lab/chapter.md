# 第一个动手实验：完成一次信任闭环

还记得开篇那道题吗？**没人做管理员，凭什么相信这笔钱是某人转给你的？** 现在我们手里恰好有两件宝，足以回答它。来把流程完整走一遍：

1. **哈希**——把"这一句话"变成指纹。
2. **签名**——用私钥对指纹盖章。
3. **验签**——全网用公钥确认："确实是那把私钥的主人授权的，而且内容没被改。"

## 完整流程（对应右侧代码）

```
Alice 想转 1 BTC 给 Bob
   │ 写下这笔交易 msg
   ▼
1) 哈希 msg ────────► 得到交易指纹 digest
   ▼
2) 用 Alice 私钥签名 digest ──► 得到签名 (r, s)
   ▼
3) 广播给全网：msg + 签名(r,s) + 公钥
   ▼
4) 每个人用公钥验签：
       内容没变？√   确实是同一个私钥签的？√
       两者都通过 → 这笔转账有效
```

## 为什么"序号 #..."很重要？

看代码第 ④ 步：把一个名字从 `Alice` 改成 `MALLORY`，验签立刻失败。但有经验的你会想到——如果某人**原封不动**重播同一笔合法的转账（"再转一次"）呢？验证一样会通过！所以在真实区块链里，每笔交易都有**唯一序号(nonce/序号)**，防止同一笔被**重放**。这个防重放话题，后面第 3 篇签名章节会专门展开。

> 💡 把 `msg` 里的名字、金额或序号改一改再运行，观察第 ① 步指纹如何"面目全非"、第 ④ 步验签是否始终失败。这就是"哈希 + 签名"组合出来的信任。
