# 对称加密在链下的用武之地：加密你的钱包

讲完哈希、签名，你可能想问：**对称加密到底用在链上的哪里？** 直接说重点：它极少出现在"链上"，但**在链下处处可见**——最典型的就是**加密钱包文件**。

## 钱包文件长什么样？

钱包软件会把你的**私钥**存进本地文件。但如果明文保存，谁拿到这个文件就把你搬空了。所以它用你的**口令**派生出密钥，再用 **AEAD 加密**后落盘：

```
口令 ──KDF──► 密钥(256位)
私钥 ────────► AES-GCM ────────► 盐 + 密文   写入钱包文件
```

这份"盐 + 密文"文件可以随便存、随便拷——因为**没有你的口令就解不开**。

## 解锁过程（对应右侧代码）

1. 读文件里的**盐**；
2. 口令 + 盐 → KDF → 密钥（每次都是同一个）；
3. `${AES-GCM}` 解密，**顺带认证**。

这样形成闭环：
- **正确口令** → 得到正确密钥 → 解密成功 + 认证通过 → 返回私钥。
- **错误口令/被篡改** → 派生密钥对不上 → AEAD 认证直接失败 → **拒绝打开**。

## 为什么必须"认证"

万一攻击者翻改文件里的密文（比如让你在不知情时用错误的私钥签名），AEAD 的标签会立刻揭穿。加密 + 认证一体，才是完整防护。
