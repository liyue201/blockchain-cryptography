# KDF 与盐：保护好你那把"钥匙串"

钱包口令往往是人能记住的"弱密码"。可加密用的是 256 位随机密钥……那**怎么把"密码"变成"可靠密钥"**？答案就是：**密钥派生函数（KDF，Key Derivation Function）**。

## 老问题：直接把密码当密钥，危险在哪？

- 密码是**人类短语**，远不是 256 位随机数，猜测空间小；
- 攻击者可以预先把常见密码和它们的哈希做成"彩虹表"，**反查瞬秒**。

## KDF 的三板斧

1. **加盐（salt）**：每个用户用**唯一的随机盐**。同密码 + 不同盐 = 不同结果，彩虹表瞬间失效。
2. **慢（迭代）**：把派生过程设计得"故意费算力"——PBKDF2 循环数万次。用户解锁只慢一点点，破解者每猜一个密码却要同样烧这么多计算。
3. **不可逆**：从密钥推不回密码，认证/校验也因此安全。

```
passphrase + 唯一salt + 迭代10000次 ──► HMAC-SHA256 ──► 32字节密钥
```

## 代码在看什么？

- `pbkdf2Like(pass, salt, 10000, 32)`：复刻 PBKDF2-HMAC-SHA256 的核心（真实库如 `x/crypto/pbkdf2` 就是它）。
- 同一个 密码+盐 ⇒ **稳定得到同一个密钥**。
- 密码改一个字符 / 盐换一下 ⇒ 密钥**面目全非**。

> 运行右侧代码，重点看：改成同一个密码、同一个盐，两次得到完全一样的 32 字节密钥；而密码尾字符一变，派生密钥立刻不同。
> 生产上主流还常用 Argon2/scrypt，思路一致：加盐 + 迭代慢 + 内存吃力。
