# 认证加密 AEAD：为什么"解密 + 认证"必须一起做

只"加密"还不够安全。你想想：如果攻击者**改动了你密文里的几个位**，你照样能解密，但得到的是**乱码**——你甚至可能没发现是被攻击了。这在大额转账场景是不能容忍的。

## AEAD：加密顺手带上"快递单"

**AEAD（Authenticated Encryption with Associated Data）** 的意思是：解密的同时，用随密的**认证标签（tag）**校验密文有没有被动过。就像快递不但封了口，还贴了张"封贴"，一开箱就能看出有没有被拆。

```
GCM 加密输出 = 密文 + 16 字节认证标签
   ▼ 解密时
先校验标签 → 通过则解密
           → 失败立刻报错（而不是给乱码）
```

## 为什么不能"先验证后解密"分开做？

历史上很多系统先加密、再单独签名，结果出现"解密预言/填充预言"一类攻击。现代最佳实践是：**把认证和加密做成一个整体**（GCM、ChaCha20-Poly1305 都是 AEAD），避免中间被钻空子。

## 代码在看什么？

- 第一次 `gcm.Open`：密文完好，出 `err=nil`，成功解出原文。
- `ct[10] ^= 0x01`：只改了密文 1 个字节。
- 第二次 `gcm.Open`：**立刻报错**，而不是输出一段乱码——这就是认证标签的作用。

> 运行右侧代码对比两次解密。**篡改哪怕一个 bit，AEAD 都会在解密瞬间识破。** 这正是它常被用于安全存储钱包私钥的原因之一。
